# 状态协议（State Protocol）

本协议定义工作区两类状态文件的内容与维护规则。

## 1. 项目状态（Project State）

文件：`state/project_state.md`

项目状态表示当前对仓库的**整体理解**。它是跨事务存在的"活文档"，随每个事务的完成而更新。

### 可以包含

- 项目目标
- 架构摘要
- 已实现的能力
- 当前开发阶段
- 已知的局限
- 已知的风险
- 技术约束
- 当前优先级
- 重要决策
- 当前事务编号

### 维护规则

- 项目状态必须描述项目**当前的实际状况**，以实际代码为准。
- **不得把推测中的未来架构当作已经存在的内容来描述。** 计划中的内容应表述为"计划 / 提案"，而不是"现状"。
- 只记录可以从仓库中验证的信息，或用户明确提供的信息；不得编造项目信息。
- 每个事务关闭时（工作流步骤 9），由执行该事务的会话更新。
- 更新是"覆盖到最新事实"，而不是追加历史 —— 历史由事务目录保留，本文件只反映当前快照。

## 2. 活动事务状态（Active Transaction State）

文件：`state/active_transaction.md`

活动事务表示**当前的开发周期**，指向正在进行中的事务。

### 应当标识

- 事务 ID
- 目标
- 当前阶段（初始化 / 规划 / 评审 / 优化 / 实现 / 验证 / 关闭）
- 参与角色
- 相关文件
- 状态（进行中 / 已关闭）
- 开始时间
- 备注

### 维护规则

- 事务初始化时写入条目；随工作流推进**及时更新**当前阶段。
- 事务关闭时（工作流步骤 10）将其标记为已关闭。
- 同一时刻只应有一个活动事务。没有任何活动事务时，本文件应明确表明这一点。

## 状态与事务的关系

- `state/` 回答"项目现在怎么样、正在做什么"
- `transactions/` 回答"每一步是为什么、怎么做的、结果如何"
- `project_state.md` 中的"当前事务"条目应与 `active_transaction.md` 保持一致
