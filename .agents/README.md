# 多智能体软件工程工作区（.agents）

`.agents/` 是一个**通用的多智能体软件工程协作工作区**，用于协调多个专门化代理角色（规划者、评审者、优化者、编码者）在软件项目上的开发工作。它是一套基于纯文本（Markdown）的协调协议，不依赖任何框架、脚本、数据库或外部服务。

## 定位与边界

- 本工作区**与具体项目无关**：角色定义和工作流协议可跨项目复用，把 `roles/` 与 `workflow/` 复制到另一个软件项目即可复用整套协议。
- 本工作区**独立于应用程序的业务架构**：它描述的是"代理如何协作"，而不是"应用如何构建"。
- 本工作区**不应包含应用源代码**，也不应包含应用源代码。
- **项目特定的信息**（架构、实现状态、当前任务、项目决策、发现的缺陷、实现结果）只存放在 `state/` 与 `transactions/` 中。
- 事务（Transaction）目录是**不可变的历史记录**，保留完整的决策链条（计划 → 评审 → 最终任务 → 实现 → 结果），保证任何决策可追溯。

## 目录结构

```
.agents/
├── roles/                        # 通用角色定义（可跨项目复用）
│   ├── planner.md                #   规划者：确定下一个有价值的工程任务并产出计划
│   ├── reviewer.md               #   评审者：对计划进行批判性评估
│   ├── optimizer.md              #   优化者：将计划 + 评审编译为最终任务规格说明
│   └── coder.md                  #   编码者：实现已批准的任务
├── workflow/                     # 通用工作流协议（可跨项目复用）
│   ├── protocol.md               #   规范工作流与角色读写分离
│   ├── state_protocol.md         #   项目状态与活动事务状态的管理规则
│   └── transaction_protocol.md   #   事务结构、编号与历史保留规则
├── state/                        # 项目特定状态
│   ├── project_state.md          #   对仓库当前状况的整体理解
│   └── active_transaction.md     #   当前开发周期的状态
├── transactions/                 # 事务历史（每个事务一个不可变目录）
│   └── README.md
└── README.md                     # 本文件
```

## 通用信息 vs 项目特定信息

| 类别 | 存放位置 | 示例 |
|---|---|---|
| 通用（与项目无关） | `roles/`、`workflow/` | 角色职责、角色约束、工作流规则、事务规则、状态规则 |
| 项目特定 | `state/`、`transactions/` | 项目架构、当前实现状态、当前任务、项目决策、缺陷、实现结果 |

**绝不要把具体的项目名称、架构、框架、业务需求或领域假设写入 `roles/` 与 `workflow/` 中的通用定义。**

## 快速开始

1. 阅读 `workflow/protocol.md`，了解完整工作流与角色读写分离。
2. 按 `workflow/transaction_protocol.md` 初始化第一个事务（见 `transactions/README.md`）。
3. 依序由规划者 → 评审者 → 优化者 → 编码者处理该事务。
4. 事务结束后按 `workflow/state_protocol.md` 更新项目状态并关闭事务，然后开始下一个事务。
