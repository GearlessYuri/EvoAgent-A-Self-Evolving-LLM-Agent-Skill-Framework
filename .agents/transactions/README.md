# 事务目录（Transactions）

本目录存放所有开发事务的历史记录。每个子目录是一个事务，完整规则见 `workflow/transaction_protocol.md`。

## 什么是事务（Transaction）

事务是针对**一个连贯的工程目标**所完成的一轮完整的"决策 → 实现 → 验证"循环。它保留了从问题识别（计划）、批判性评估（评审）、最终决策（任务规格说明）到实现与结果的完整链条，使历史决策可追溯。

## 事务 ID 如何分配

- 使用顺序编号，四位零填充：`0001`、`0002`、`0003`、……
- 新事务 ID = 当前最大事务编号 + 1
- 编号一经分配永不复用，即使某个事务被放弃

## 每个事务包含哪些文件

```
0001/
├── context.md     # 事务开始时的相关项目状态（时间胶囊）
├── plan.md        # 规划者的提案
├── review.md      # 评审者的发现
├── task.md        # 优化者的最终可执行任务规格说明
├── execution.md   # 编码者实际做了什么，包括重要的实现决策
└── result.md      # 最终结果：变更文件、测试、验证、局限、后续建议
```

各文件的详细用途见 `workflow/transaction_protocol.md`。

## 历史事务应如何保留

- 事务关闭后**不重写**其文件；更正明确的事实性错误除外，且需注明更正说明。
- 新的工作永远开新事务，而不是修改旧事务。
- 引用历史时使用事务 ID（例如："见事务 0003 的 `result.md`"）。

## 新事务应如何初始化

1. 确定下一个事务 ID（当前最大编号 + 1；当前没有任何事务时为 `0001`）。
2. 创建 `transactions/<ID>/` 目录及 `context.md`，记录事务开始时的相关项目状态。
3. 更新 `state/active_transaction.md`（事务 ID、目标、状态、当前阶段、开始时间等）。
4. 更新 `state/project_state.md` 中的"当前事务"条目。
5. 按工作流协议（`workflow/protocol.md`）进入规划阶段，由规划者产出 `plan.md`。
